# Specter Audit — independent first-use task (M203)

**Voluntary, about 5 minutes.** This is a public, read-only study of a developer tool, not a request to review private code or a production pull request. The sample case includes a redacted, editable saved Kiro session; the Arena challenge is an **owner-controlled demonstration**. Neither is independently attested. Honest confusion or negative feedback is useful.

**Start here:** [Submitted Kiroween M130 demo](https://specter-audit-pi5tpg7i7-nvhoa1691993-6852s-projects.vercel.app/) — no account, install, upload, or access token required. The [public feedback issue #28](https://github.com/ShenJun93/specter-audit/issues/28) is optional; posting a reply there requires a GitHub account, and the reply is public.

If possible, **try the tasks before reading the project README or judge guide**. The demo itself previews the 120-test/five-edit chronology before the finding is revealed, so this is **not a blind test**. We want to understand your interpretation of the evidence's limits and your next review action, not whether you can repeat those numbers. You can stop or skip any part.

## Task A — would you trust the agent's completion claim?

Open the demo and follow **Judge Fast Path**. Inspect the case titled **The midnight rewrite** (Case 04). After viewing the finding, answer in your own words:

- What did the evidence actually establish, and what remains unknown?
- What would you ask the coding agent or the reviewer to check next?

## Task B — would you approve the PR?

From the demo open **Specter Arena**. Inspect the public case, its provider CI evidence and the reviewer challenge. Decide whether you would approve the code based on what you see.

- What evidence is strongest?
- What does that evidence *not* establish?
- What would you verify before allowing a merge?

No claim is made that this fixture represents an external customer's code.

## Task C — does this solve a real problem?

Would you use a tool like Specter Audit when reviewing AI-generated code? Answer **yes / maybe / no** and explain the single largest adoption blocker. If any label, navigation step or evidence boundary was unclear, mention it.
