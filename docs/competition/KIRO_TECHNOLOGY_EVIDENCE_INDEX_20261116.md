## Native Kiro hook experiment — M155–M157 (not shipped)

**Command dispatch was observed; agent delivery was not.** In a separate, owner-approved, disposable Kiro CLI 3.1.0 experiment on 2026-11-13, two actual `PostFileSave` events generated by Kiro source-file writes invoked an isolated **command hook**. Bounded independent wrapper receipts `M157_HOOK_REAL_EVENT_01.json` and `_02.json` each recorded `actualHookCommandDispatched:true`, a **Windows-absolute** `file_path`, a fixed handler `WARNING`, process exit `0`, and no child stderr. The local receipt SHA-256 values are `577579ec11a668e64c98f331f6ba6cbd49614dc02c8cf02b8e4acfa009682d65` and `99811b8bfe771c0872163f0b8fd0092460ef91dc050992727ad14fbd955308c1`. See the [original M157 public evidence summary](https://github.com/ShenJun93/specter-audit/pull/24#issuecomment-6844697929).

**Critical boundary:** The Kiro agent explicitly reported `HOOK_OUTPUT_NOT_VISIBLE`; the separately verified `M157_FOCUSED_REAL_KIRO_AGENT_CONTEXT_RESULT.json` receipt had `status:HOOK_FIRED_CONTEXT_NOT_CONFIRMED` and `agentContextSupportedByExactQuote:false` (SHA-256 `ba0a8937ce131ac47209b9f2e5553f16710df4929185192acebbb4a72b3e4c2f`). Thus the hook **command ran and generated the bounded warning**, but there is no proof that the agent received, understood, or acted on the warning; no automatic retest was established. Raw Kiro transcripts remain private, and these editable local receipts are not signed independent attestation.

**Attribution:** Kiro wrote an early handler/tests in the isolated M155 prototype; **ChatGPT/WAG**, not Kiro, implemented M156 Windows absolute-path compatibility and follow-up QA. This experiment was never merged or deployed. The separate M260/M264 Kiro CLI 3.3.0 prototype was loaded but produced no observable warning in the agent context, and it remains disabled/unmerged. See the [M272 reconciliation in Issue #40](https://github.com/ShenJun93/specter-audit/issues/40). **No functioning agent-visible native hook is claimed in the submitted M204 demo.**

## Strategy and experimentation (aligned with the judging criterion)

- **Thoughtful AI-development strategy:** committed [Kiro steering](../../.kiro/steering/product.md) defines read-only Git, no arbitrary shell execution, limited trust vocabulary and evidence provenance. [Root Kiro specs](../../.kiro/specs/) specify requirements and tasks. Their presence is verifiable; their authorship by a particular agent is **not** independently attested.
- **Core Kiro coding work:** actual CLI file edits to engine/adapter/auditor/test code, not just ideation. Public commits and bounded local session reports establish the *scope of the claim*.
- **Experimentation and failure handling:** the M5A stale-test sequence became a public Case 04; M6E adversarial tests reproduced false positives before remediation; M118 explicitly records the blocked tool permission instead of inventing a passing test.
- **Variety of Kiro features — evidence and known limit:** verified CLI file-edit workflow and project specs/steering are the primary Kiro implementation evidence. M157 additionally demonstrated **genuine isolated PostFileSave command dispatch and fixed-warning generation** (twice), but agent-context delivery remained unverified and the hook was never shipped. **No working agent-visible native hook, Crew app, custom agent, MCP, power or PBT is claimed for M204.** Do not promote prototype results into a deployed capability.
