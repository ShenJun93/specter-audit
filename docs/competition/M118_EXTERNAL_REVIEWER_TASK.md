# M118 — External evaluator task sheet

Status: prepared, **not conducted**. Ask for voluntary consent before collecting or publishing any personal feedback. Do not claim external adoption without independently performed tasks.

Reviewer briefing: "You are reviewing an AI coding agent's completion claim. Open the Specter Arena Preview and the linked public fixture PR. You do not need to log in or upload anything. This is a synthetic owner-controlled PR, not a real customer's repository."

Without further instructions:
1. In 60 seconds, describe what the green GitHub CI checks and the base/head behavioral challenge each establish.
2. Find the base commit and head commit. Say whether the challenge demonstrates a fix, a regression, both pass, both fail or an unknown result.
3. Identify at least two limitations before treating the PR as approved.
4. Explain the next action you would take and where the source evidence came from.

Record **only with permission**: reviewer category (not identity), first useful outcome time, whether their interpretation was correct, navigation issues, confusion about attestation, and whether the product would help review an actual PR. Report failures and adverse feedback, not just successes. Do not upload their logs, usernames, private code, test output, or contact details. Use 3–5 external reviewers if practical; mark an owner-controlled test separately.

Acceptance gate for stronger impact claims: at least three genuine external evaluations with reproducible timings and explicit scope. If none, disclose zero external validation rather than presenting fake testimonials.
